# Security reporting

For a published GitHub repository, use Security → Advisories → Report a vulnerability to contact maintainers privately. Enable private vulnerability reporting when publishing. Do not post credentials, customer mail or exploit details in public issues.

Until a public repository exists, report privately to the maintainer through the existing private project channel. No security contact address is embedded in this distribution.

Keep secrets and real company packages outside the public repository. Use HTTPS in production, preserve persistent state across upgrades, and configure only the intended MCP hostname. The system handles approved content; AI validation does not replace staff review or establish legal eligibility and price applicability.
